# Review agenda — owner's 18 questions (drive the W7 critic + fact-verification + dialogue)

Process (owner, 2026-06-12): after the build is complete, run the independent critic (opus, harsh, no hints — see critic mandate); then RE-VERIFY every factual answer with at least two external confirmations (the code itself + the internet / reference repos); answers must never be invented. Then a brief AskMe dialogue with the owner over these 18 points until shared understanding ("we mean the same thing, the task is understood and done correctly"). NO fixes are written during the dialogue — dialogue only. The deliverable is a full result-of-dialogue file with anchors and facts.

Each answer below must carry: (a) a code anchor (path:line) and (b) an external confirmation (reference repo / official doc / web) — or an explicit "no honest data, cannot conclude".

## The questions (verbatim, RU)

1. Как написан код? Есть ли плохие паттерны и code smells?
2. Секреты и токены — на хосте? В контейнер пробрасывает что? Изоляция соблюдена?
3. Код разбит по модулям? Пайплайн надёжен, полиси тасок есть? Шаги заменяемы?
4. Телеграм в итоге готов к работе? Чтобы я в меню вбил токен и клод мог писать/читать в канал.
5. Лишние документы, .md файлы и другие (не код) вещи — должны быть вычищены, code-first подход.
6. Меню удобное? Я могу как человек видеть промежуточный процесс пайплайна, пропускать опциональные ошибки?
7. Не осталось ли старых файлов, архитектуры, бессмысленных тестов на keychain, например?
8. CI соответствует инженерным практикам? Шаги имеют зависимости друг от друга или гоняются разом? Есть ли предустановка пакетов/среды первыми шагами?
9. Изменения обрезают какой-то старый функционал?
10. Тесты покрывают пользовательские сценарии, тестируют разные кейсы, а не тесты ради покрытия / "тест зелёный — код рабочий"? Arrange-Act-Assert?
11. "Как пользователь работает с программой": запустил в терминале — что видит в меню? Что если запуск долгий — виден ли прогресс? Есть ли шаги в неверном порядке?
12. Гуглили/проверяли — но не факт что не костыли/велосипеды. Как убедиться?
13. Дедлоков быть не должно — каждый путь критический (полноценная система, не набор нейрослопа).
14. После мержа: запустить песочницу с нуля — она сама всё качает/ставит, я только выбираю конфигурацию и жду. Так ли это? Никаких ручных сложных действий.
15. Соотносится ли всё с целями песочницы: разграничение ответственности, автономность, надёжность, простота, гибкость, масштабируемость?
16. Процессы: UI-процесс рулит потоками-задачами-шагами. После запуска и открытия CLI claude — терминал в валидном состоянии? Копирование текста работает? Нет ли зависаний/поломок из-за кривого кода? Соблюдён ли принцип систем (вход/выход/связи/потоки данных)? Есть ли ботлнеки?
17. Линтеры, конфиги — нет ли ненужного/непроверенного нейрослопа или констант?
18. Где был не прав, где противоречия, где обманул себя/меня? Где данных честно нет и вывод невозможен? Где переусложнил? Где сделал костыль "лишь бы работало"?
