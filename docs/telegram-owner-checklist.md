# Чеклист владельца: Telegram-канал A↔D

Ручные шаги, которые нельзя автоматизировать. Выполнить один раз перед запуском трубы.

## 1. Защита аккаунтов

- [ ] Включить двухфакторную аутентификацию на обоих аккаунтах Telegram:
  Настройки → Конфиденциальность и безопасность → Двухэтапная верификация.
- [ ] Добавить резервный e-mail для восстановления в настройках двухэтапной верификации.

## 2. Создание приватного канала

- [ ] Создать **приватный канал** (не группу): «Новый канал» → тип «Приватный».
  Причина: боты не видят сообщения друг друга в группах; в канале `channel_post` доступен обоим.
- [ ] Записать числовой ID канала (показывает `tgsmoke` или `/getChat` в API).

## 3. Боты через BotFather

- [ ] Создать бота A: `/newbot` в @BotFather, записать токен в файл с правами `0600`.
- [ ] Создать бота D: `/newbot` в @BotFather, записать токен в файл с правами `0600`.
- [ ] Токены **никогда** не попадают в git, логи, переменные окружения процессов.
  Хранить только в файлах-секретах (`/run/secrets/...` или аналоге).

## 4. Права ботов в канале

- [ ] Добавить бота A в канал как администратора:
  Управление каналом → Администраторы → Добавить.
  Права: **только «Публикация сообщений»**. Снять: редактирование, удаление, приглашение.
- [ ] Добавить бота D в канал как администратора с теми же ограниченными правами.

## 5. Смоук-тест

- [ ] Запустить `tgsmoke -token-a <файл-A> -token-d <файл-D> -channel <id>`.
  Ожидаемый результат: `PASS: bot D received the canary channel_post`.
  При `FAIL`: задокументировать и переключиться на запасную схему (человек-читатель).

## 6. Обмен recipient-строками age (личная встреча)

- [ ] Сгенерировать ключевую пару age для стороны A: `age-keygen -o identity-a.txt`.
- [ ] Сгенерировать ключевую пару age для стороны D: `age-keygen -o identity-d.txt`.
- [ ] Обменяться **публичными** recipient-строками (строка `# public key: age1...` из файла)
  лично или по каналу, который обе стороны считают доверенным.
  Приватные identity-файлы **не покидают** своё устройство, `chmod 600`.
- [ ] Каждая сторона хранит identity-файл **вне** директории workspace/git.

Примечание: реализация age-обёрток — следующий PR (вне данного скопа).

## 7. Процедура отзыва (kill-switch)

- [ ] Отработать процедуру один раз в тестовом режиме:
  1. Открыть @BotFather → `/mybots` → выбрать бота → API Token → Revoke.
  2. Убедиться, что `tgsmoke` возвращает `FAIL` с отозванным токеном.
  3. Выпустить новый токен через `/revoke` → записать в файл-секрет → перезапустить процессы.
- [ ] Задокументировать контакты для экстренного отзыва (кто может добраться до файла-секрета).
