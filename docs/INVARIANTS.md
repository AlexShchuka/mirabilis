> **Провенанс: инварианты I1–I8 — [ВЛАДЕЛЕЦ] (прямые формулировки владельца).** I9 и
> I-Telegram — **[ИИ]** (выведены ассистентом в PR «coherent box», ждут подтверждения
> владельца). В колонке «Граница/нюанс» добавления ассистента помечены [ИИ].

| # | Инвариант [ВЛАДЕЛЕЦ] | Почему | Граница / нюанс |
|---|---|---|---|
| **I1** | `mirabilis` — **единственная команда** | минимум ритуала; «одна команда» — суть UX | подкоманд `update/down/restart/token` в ежедневном флоу нет; всё делает запуск через меню. [ИИ]: реализовано в PR «coherent box» — подкоманды убраны, `mirabilis` открывает TUI-меню (см. [VISION.md](VISION.md) §7) |
| **I2** | Внутри можно установить/изменить **что угодно**, включая `apt` | универсальная песочница под любой стек | требует **root внутри**; не нарушает I5 |
| **I3** | Claude запускается с `--dangerously-skip-permissions` (**bypass**) | полная автономия — ради этого песочница | под bypass нативный `ask` не работает — и это ОК: внутри контейнера ворот согласия нет (см. I6), граница = сам контейнер (I5) |
| **I4** | Несколько окон × `mirabilis` = несколько сессий на **одном** контейнере, стабильно | реальный рабочий паттерн | при здоровом окружении — идемпотентный attach; обновление останавливает контейнер и убивает все сессии (осознанно). [ИИ]: при attach действует fail-fast-проверка критичного — см. I7 |
| **I5** | **Изоляция хоста = надёжность**: контейнер не влияет на Mac | «надёжность» в нашей терминологии именно это | внутреннюю мутабельность не ограничивает |
| **I6** | Внутри контейнера **защиты файлов нет**: граница безопасности — **сам контейнер** (I5) | mirabilis не сторожит внутренности; bypass и нужен ради полной автономии (I3) | внутри — **полная свобода** (I2: root, любые файлы, `sudo`, харнес, система); сломал своё окружение — рестарт пересоберёт. [ИИ]: **поведенческие лимиты** (не ломать ЧУЖОЕ — push/force в `main`, эксфильтрация кредов наружу) — дело **харнеса neuro-matrix** (его инварианты + хуки), а не песочницы mirabilis. Внутри контейнера ворот согласия / protected-paths / denyWrite больше нет |
| **I7** | **Fail-fast** на критическом пути | не работать в сломанном окружении | [ИИ]-уточнение (F3): **зависит от компонента** — egress/Claude-токен = стоп с диагностикой даже при тёплом attach; **харнес опционален → варнинг** (режим bare), не стоп; мелочи = варнинг |
| **I8** | При конфликте **простота > надёжность > безопасность-от-эксфильтрации**; воспроизводимость — не цель | приоритеты заданы владельцем | калибрует все спорные решения |
| **I9** [ИИ] | **Конфигурация ≠ действие** | предсказуемость: выбор в меню не меняет систему «втихую» | пункты меню пишут только декларативное состояние (плагины/харнес/стек/секреты в файлы и `.env`); применение — только при старте контейнера (entrypoint → идемпотентный `refresh.sh`). `do_plugins`/`do_harness` `refresh.sh` при выборе **не** запускают. Смена стека не пересобирает сразу — помечает workspace «stale → rebuild on launch». Исключение: «harness reinstall» — узкий путь, переустанавливающий **только** neuro-matrix, ничего больше |
| **I-Telegram** [ИИ] | **Уведомления — только наружу**, осознанное исключение из I5 | владельцу нужен «зуммер» о готовности/вопросе, не нарушая изоляцию | один домен `api.telegram.org`, единственный `chat_id`, **односторонний** канал (`Stop` → «✅ готово», `Notification` → «❓ нужен ответ» через `sendMessage`); **нет** webhook / long-poll / входящего управления — Телеграм лишь зуммер, отвечает владелец в терминале. Токен+`chat_id` — Keychain хоста → env контейнера. Не общий шлюз эксфильтрации: единственный адресат — сам владелец |

## Производные правила [ИИ] (выведены из инвариантов)

- Мутабельность **всего**, включая системные файлы и харнес; защита = граница контейнера (I5), а не внутренние ворота.
- Персистентность: переживает рестарт только то, что в persistent volume или в declared-list,
  применяемой при старте (см. [ARCHITECTURE.md](ARCHITECTURE.md) §5).
- Универсальность (I2) конкретизируется как «любой проект/стек» при одном контейнере на много репо.
- **Конфигурация ≠ действие (I9):** декларативный выбор отделён от применения; применение
  идемпотентно и происходит при старте, а не в момент клика по меню.

## Происхождение

Инварианты выведены из прямых формулировок владельца. I1 и I2 названы инвариантами дословно; I3 —
«bypass, для этого мы и делаем песочницу». Полный журнал «вопрос → ответ» — в [DECISIONS.md](DECISIONS.md).
